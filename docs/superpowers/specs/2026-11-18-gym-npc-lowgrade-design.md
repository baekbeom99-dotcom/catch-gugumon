# 체육관 + 트레이너 NPC, 셈연습 트레이너, 저학년 모드, 건물 그림자 — 설계

앞선 설계(`2026-11-18-training-center-design.md`)를 **바꾸는** 설계다. 트레이닝센터 건물 12채는 없애고, 같은 학습·도전 화면을 체육관 안의 트레이너 NPC가 맡는다. 이 브랜치(`training-center`)는 아직 main에 합치지도 배포하지도 않았으므로 그 위에서 이어 고친다(배포된 저장에 영향 없음).

## 왜
- 마을에 건물 12채가 늘어서는 대신, 포켓몬 체육관처럼 **한 채 + 안에서 트레이너와 겨루는** 구성이 아이에게 이해하기 쉽고 재미있다.
- 셈연습(덧셈·뺄셈·보수)도 같은 방식(트레이너 NPC)으로 들어오게 하고, 저학년은 구구단 대신 덧뺄셈으로 구구몬을 잡게 한다.

## 사용자가 정한 것
**체육관**
1. 태초마을에 체육관 한 채(첫 번째 사진 배치: 큰 건물 + 옆 표지판 + 앞길). 트레이닝센터 12채는 모두 삭제. **11단은 삭제.** 단 트레이너는 2~9, 12, 13단(10명), 순서대로 열림(9 다음 12, 그다음 13).
2. 체육관 **안**은 별도 실내 지도(두 번째 사진처럼): 위쪽 장식 벽, 분홍 타일 바닥, 가운데 단상, 아래 입구(파란 매트). 트레이너 NPC가 서 있다. NPC에게 말을 걸면(부딪히면) 지금의 **차례대로 학습 / 마스터 도전** 선택 화면이 열린다.
3. 마스터 보상: **해당 도전을 처음 마스터할 때만 그 단의 캡슐 20개**. 그 밖에는 **성공 시 5개** 지급. 성공 = 학습을 끝까지 마침 / 도전 합격. **도전에 실패하면 캡슐은 없다**(앞서 "실패해도 끝까지 가면 5개"였던 규칙을 "성공시"에 맞춰 바꿈 — 별점수 3개와 같은 기준). 첫 마스터에는 20개(5개가 더해지지 않음). 12·13단 첫 마스터는 레전드 구구몬 1마리도 지급(기존).
4. 마스터한 NPC는 **머리색이 노랑**으로 바뀐다. (지붕 숫자는 건물이 없어졌으므로 없앤다.)

**셈연습 트레이너 NPC (체육관 안)**
5. 그림은 `013` 폴더 이미지(치비). 013은 **레전드에서 제외**하고 종 목록에서도 뺀다(NPC 전용 그림). NPC마다 **RGB 색**을 바꿔 서로 구분한다.
6. 셈연습 트레이너는 **마스터 도전만** 있다(9문제). 마스터 기준은 기존과 같다(`PRACTICE_MASTER_SEC_PER_Q`: 기본·보수 문제당 3초, 고수 5초 → 9문제 전체 27초/45초/27초, 하나도 안 틀림).
7. **고수 단계 마스터** 시 레전드 구구몬 지급. 셈연습 보상은 **무작위 캡슐**.
8. 마스터한 트레이너 NPC는 머리색이 노랑으로 변한다.

**저학년 모드**
9. 타이틀 화면에서 켠다. **켤 때도 끌 때도 비밀번호 `1234`를 입력해야 바뀐다**(틀리면 바뀌지 않고 "비밀번호가 맞지 않아요"). 어른이 정하는 설정이라는 뜻의 작은 자물쇠 확인이다. 켜면 **구구몬 잡는 문제**가 덧뺄셈으로 바뀐다: 초원 = 한 자리 + 한 자리, 한 자리 − 한 자리 / 물가 = 두 자리 − 한 자리 / 사막 = 두 자리 + 한 자리.
10. 캡슐 구입 연습: 그 지도(필드)의 문제 5개. 회복 연습: 틀린 문제, 없으면 무작위 문제. **체육관은 그대로**(구구단).

**그림**
11. 건물(체육관·상점·집·무한의 계단 건물 등)에 **그림자**를 만든다(앞서 캐릭터 그림자와 같은 결).

## 목표 / 비목표
- 목표: 위 11가지. 수치·표는 한 곳(`tuning.ts`와 NPC 표 파일 하나)에 둔다.
- 비목표: 배포된 저장 이전(배포 전), 체육관 관장 같은 새 전투, 셈연습의 개별 10종을 각각 NPC로(단계별 3명으로 함), 퀴즈모험 부활.
- 반(反)목표: 저장 손상, 이미 만든 학습·도전 화면·러너·보상 중복 방지 규칙을 다시 만드는 것(재사용), 저학년 모드에서 아이가 막다른 화면을 만나는 것.

## 접근
1. **채택** — 기존 트레이닝 구현을 "건물 문" 대신 "NPC 말 걸기"로 연결하고, 체육관 안을 새 지도(`gym`)로 만든다. 학습·도전 화면(`TrainingScreen`·`flow`·`runner`)·저장 `field.training`·훈련 보상 로직을 그대로 쓰고 입구만 바꾼다. 셈연습은 같은 도전 화면을 문제 공급만 바꿔 재사용한다.
2. 체육관 안 지도를 만들지 않고 마을 지도 위에 NPC만 세움 — 사진(실내 구성)과 맞지 않아 제외.
3. NPC를 건물 대신 DOM 팝업 목록으로 — "서 있는 NPC에게 걸어가 말 건다"는 요청과 맞지 않아 제외.

## 설계

### A. 체육관과 NPC
- **마을 지도**: 맨 위 훈련 거리 줄을 없애고 체육관 한 채 + 표지판 + 앞길을 둔다(구성은 사진 1: 건물 아래 가운데 문, 왼쪽 표지판, 앞에 넓은 길). 무한의 계단 건물은 그대로 마을에 남긴다(제 판단). 줄 수가 바뀌므로 `TOWN_ROWS_ADDED`를 새 값으로 고치고 옛(main) 마을 39줄과 칸이 같은지 보는 테스트는 유지한다. 체육관 문에 부딪히면 `gym` 지도로 간다(`doors` 종류 `gym`, `travelTo` 사용).
- **체육관 지도(`gym`)**: 새 `MapId`. 이 지도는 구구몬이 나오지 않는다. 출구는 아래 입구 하나(마을 체육관 문 앞으로 돌아옴). 가운데에 장식 단상, 바닥·벽 타일, NPC 칸은 걷지 못하는 칸. `TOWN`처럼 지도 글자·NPC 표(`GYM_NPCS`)·표지판 글을 `gym.ts` 한 곳에 둔다.
- **NPC 표(한 곳)**: `{ id, kind: 'dan'|'arith', dan? | level?, pos, tint: [r,g,b] 곱셈 또는 색상 변환 }` — 단 트레이너 10명(2~9,12,13), 셈연습 3명(기본·고수·보수). 한 명 한 칸씩 사진처럼 흩어 배치하고 번호는 열림 순서다.
- **열림 규칙**: 단 트레이너는 `TRAINING_DANS = [2,…,9,12,13]` 순서로 앞 NPC를 마스터해야 말 걸 수 있고, 잠겨 있으면 "○단 트레이너를 먼저 이겨요" 글. 셈연습 트레이너는 처음부터 열림(제 판단: 구구단 진행과 별개).
- **말 걸기**: NPC 칸에 부딪히면 그 NPC의 화면으로 간다: 단 트레이너 → 기존 `/field/training/:dan`, 셈연습 → 새 `/field/training/arith/:level`(마스터 도전만, 같은 `QuizBoard`·`runner`·결과 화면 재사용). 돌아오면 체육관 안, 말 건 NPC 앞 칸에 선다. 효과·보상 판정은 기존 그대로.
- **보상**: `finishTraining`의 캡슐 수를 "그 단을 처음 마스터한 도전이면 20, 아니면 5"로 바꾼다(`TRAINING_CAPSULES = 5`, `TRAINING_FIRST_MASTER_CAPSULES = 20`). 캡슐 종류 표는 그대로(2~9단 해당 필드, 12·13단 황금), 11단 항목 삭제. 셈연습: `field.training.arith`에 단계별 `{ studied?, mastered: {bestMs, at} }`를 더하고 **처음 마스터 20개·그 밖의 성공 5개**를 무작위 필드 캡슐(초원·물가·사막)로(제 판단: 황금은 제외), 고수 첫 마스터는 레전드 구구몬 1마리(`legendGranted`에 `arithHard`).
- **013 제거**: `SPECIES_IDS`·`LEGEND_SPECIES`·이름·속성 표에서 `c013` 삭제 → 종 48, 레전드 11, 빛 속성 6마리. 속성 균형 테스트·도감 분모·SPECIES 개수를 갱신. 이미 `c013`을 잡은 저장은 `OLD_SPECIES_MAP`에 `c013 → c046`(빛 레전드, 제 판단)을 더하고, 둘 다 있으면 `c046` 쪽만 남기고 `c013`은 버린다(손실 최소 규칙은 구현자가 테스트로 고정).
- **NPC 그림·색**: 013 치비(front/idle/walk, 4방향)를 NPC 모양으로 쓴다. 이미지가 없으면(배포 빌드) 픽셀 폴백(단순 사람 모양) — 색 변환은 같은 표를 쓴다. 색 구분은 **NPC마다 RGB 곱셈/색상 이동**을 캔버스에서 한 번 구워 캐시(`companionImage`처럼 rAF·setTimeout 안에서). 머리(주황 계열 화소)는 몸 색 변환에서 제외해 두고, **마스터하면 머리 화소를 노랑으로** 바꿔 굽는다(색상 범위 마스크).

### B. 저학년 모드
- **설정**: `Settings.lowGrade: boolean`(기본 false). 타이틀에 작은 스위치(켜짐 표시). 스위치를 누르면(켤 때·끌 때 모두) 숫자 입력창(기존 관리자 PIN 입력 화면 `PinPad` 형태가 있으면 재사용)이 뜨고, 비밀번호 `LOWGRADE_PASSWORD = '1234'`(`tuning.ts` 한 곳)와 같을 때만 `lowGrade`를 바꾼다. 이것은 아이가 실수로 바꾸지 않게 하는 확인일 뿐 보안이 아니다(코드에 값이 들어 있음, 제 판단 — 관리자 PIN 해시 방식과 별개). 입력 틀림은 잠금 없이 다시 입력, 취소하면 그대로. 저장은 `mergeSave`에서 기본값 채움(Settings 깊은 병합은 기존 방식).
- **문제 공급**: `fieldQuestions`(야생 전투 문제)에서 저학년이면 필드별 덧뺄셈 문제를 낸다: 초원 → 기본 단계(`addNoCarryBasic`·`addCarryBasic`·`subNoBorrowBasic`·`subBorrowBasic` 중 한 자리), 물가 → 두 자리 − 한 자리(받아내림 있음·없음 섞음), 사막 → 두 자리 + 한 자리. 기존 `arith.ts` 문제 생성기를 쓰고, 두 자리 ± 한 자리는 `arith.ts`에 새 종류를 더한다(수치·범위 한 곳). 문제 시계·정답 판정·기술 조건 시간은 그대로(구구단 문제 시간 표를 덧뺄셈에도 같은 규칙으로 쓰되 값은 구현자가 `tuning.ts`에서 정함).
- **상점**: 캡슐 구입 = 그 필드 문제 5개(필드 하나, 필드의 문제 종류로), 회복 연습 = 틀린 문제(저학년 모드에서 틀린 문제는 `field.lowGrade.recentWrong`에 최근 몇 개를 저장), 없으면 그 구구몬 필드의 무작위 문제. `planShopQuestions`·`planHealQuestions`에 저학년 갈래를 더한다.
- **체육관·트레이닝은 그대로**(저학년 모드와 무관).
- **레전드 구구몬 만남**: 그 필드의 저학년 문제를 따른다(제 판단).

### C. 건물 그림자
- 마을·필드 건물(체육관, 상점, 집, 무한의 계단 건물, 담)에 `shadow.ts` 방식의 그림자: 건물 발치 한 칸 아래·오른쪽으로 연한 어두운 띠를 타일 레이어에서 그린다(정적이라 캐시 가능). 크기·농도는 상수 한 곳.

### D. 정리해야 할 것(기존 구현의 바뀜)
- 삭제: 마을 훈련 거리 줄·건물 타일(`trainWall`·`trainDoor`), `roofNumberRects`와 지붕 숫자 그리기, `doors`의 `training` 종류, 11단 관련 표·E2E.
- 바뀜: `doorEntry`(문 종류 `shop|gym|stairs`), `TRAINING_DANS`, `TRAINING_CAPSULE_OF_DAN`(11 삭제), `finishTraining`(20/5 규칙, 첫 마스터 판정), 마을 지도·`TOWN_ROWS_ADDED`, `training.ts`의 `isTrainingOpen` 목록, 트레이닝 E2E(건물 → NPC), 설계서·CLAUDE.md.

## 확인
- 단위: 새 `TRAINING_DANS`, 첫 마스터 20/성공 5 규칙, 셈연습 판정·보상(무작위 캡슐 종류는 시드 고정), 013 제거 후 종 개수·속성 균형·이전, NPC 표(위치가 걷는 칸 바로 옆·중복 없음), 색 변환 순수 함수(주어진 화소 → 변환 화소, 머리 마스크), 저학년 문제 범위(초원 한 자리 등), 상점 5문제·회복 규칙, 설정 병합.
- E2E: 마을 체육관 문 → 체육관 안 → 2단 NPC 말 걸기 → 학습 → 도전 → 머리색 변화, 잠긴 NPC 글, 셈연습 NPC 도전(마스터만), 저학년 모드 토글 후 초원 문제 형태.
- 화면: 375px에서 마을 체육관, 체육관 안, NPC 색 구분·머리색 노랑, 그림자.

## 추가: E. 별점수(화폐) 시스템 — **코드로 만들어 두되 전부 꺼 둔다**
**사용자가 정한 것**
- 새 화폐 "별점수"(퀴즈모험의 `economy.stars`와 별개). 얻는 길: 새 구구몬 발견 5개, 새 구구몬 포획 5개, 트레이닝 성공 3개(캡슐 보상과 함께), 체육관 **동상**에게 말 걸기(아래). 쓰는 곳은 주인공 **코스튬**(이번 범위 아님).
- 동상(체육관 지도 아래쪽 회색 동상 둘): 말을 걸면 **랜덤 7문제**. 항상 **12단 또는 13단 문제가 한 문제** 들어가고, **틀린 문제 중심**으로 낸다. 푸는 시간에 **반비례해 별점수 5~15개**(빠를수록 많이). **저학년 모드**에서는 덧뺄셈의 틀린 문제 중심 + 랜덤(12·13단 규칙은 구구단 쪽에만).
- **코스튬이 나오기 전까지 비활성화: 적립도 화면도 모두 끈다**(사용자 선택). 켜기 전에는 별점수가 쌓이지 않고, 동상은 말을 걸어도 아무 일이 없는 장식이다.

**설계**
- `src/config/featureFlags.ts`에 `STAR_POINTS_ENABLED = false`와 `isStarPointsEnabled()`(E2E `__GUGU_E2E_STARS__` 우선, 퀴즈 플래그와 같은 방식). 꺼져 있으면: 별점수를 더하는 호출이 아무것도 하지 않고(저장도 안 바뀜), 필드 HUD·결과 화면에 별점수가 보이지 않으며, 동상은 말을 걸어도 반응이 없다(걷지 못하는 장식 칸).
- 저장: `SaveData.field.starPoints: number`(정수, 0 이상, 기본 0)를 **항상** 형식에 넣는다(네 곳: `createInitialSave`·`mergeSave` 깊은 채움·`partialize`(field 통째)·`currentSave()`). 켜기 전에는 0 그대로.
- 규칙은 순수 도메인 `src/domain/field/starPoints.ts` + 수치는 `tuning.ts`: `STAR_DISCOVER = 5`, `STAR_CATCH = 5`, `STAR_TRAINING = 3`, `STATUE_QUESTIONS = 7`, `STATUE_STARS_MAX = 15`, `STATUE_STARS_MIN = 5`, 시간 → 별 변환(`statueStars(timeMs)`: 가장 빠른 기준 시간 이하면 15, 느린 기준 시간 이상이면 5, 사이는 시간에 반비례로 정수 보간 — 기준 시간은 `tuning.ts`). 문제 계획 `planStatueQuestions(facts, field, lowGrade, rng)`: 12 또는 13단 한 문제를 반드시 넣고 나머지는 틀린 문제 우선(기존 `planHealQuestions` 방식 재사용), 저학년이면 덧뺄셈.
- 적립 연결(꺼져 있으면 전부 no-op): 새 구구몬 발견(`markSeen`의 새 종), 새 구구몬 포획(`finishWildBattle`의 새 종), 트레이닝 성공(`finishTraining` 학습 완료·도전 합격 — 실패는 별 없음), 동상(새 액션 `finishStatue({ timeMs, correct })`: 전부 맞혔을 때만 지급 — 틀린 문제가 있으면 별 없음은 제 판단).
- 그래서 지금 구현 범위: 저장 형식, 순수 규칙·수치, 스토어 액션들(호출은 되지만 꺼져 있어 효과 없음), 동상 화면은 문제 계획과 화면 틀까지(플래그 켜면 동작). 단위 테스트는 플래그를 켠 상태와 끈 상태 모두를 고정하고, E2E는 끈 상태에서 "별점수 변화 없음·동상 반응 없음"을 확인(켠 상태 흐름은 `__GUGU_E2E_STARS__`로 한 가지 시나리오).

**제 판단**: 동상은 하루 한도 없음(켜는 날 다시 정함) / 동상 별점수는 7문제 전부 맞혔을 때만 / 별점수 표시 자리는 켤 때 정함(필드 HUD 알약 옆 후보) / 저장 형식은 지금 넣는다(켠 뒤 저장 변경이 없도록).
- 저학년 모드 비밀번호는 고정값 `1234`(코드에 들어 있는 간단한 확인, 보안 아님). 관리자 PIN과 별개로 두며 값은 `tuning.ts` 한 곳. E2E는 `1234` 입력 흐름을 확인.
