# 필드 모험 3차 — 설계서

> 기준: 2차(`2026-11-11-field-adventure-2-design.md`) 위에 얹는다. 수치는 `src/domain/field/tuning.ts` 한 곳, 저장은 `SaveData.field`(키 `gugu-monster:save`).
> 사용자 요청(2026-11-12)과 답을 옮긴 것이며, "가정"으로 표시한 곳만 내가 정한 것이다(수치는 `tuning.ts`·`skills.ts`·`elements.ts` 한 곳에서 바꾼다).

## 0. 요청 한눈에

1. 캡슐 포획에 실패하면 **적이 체력을 일부 회복하고 다시 싸운다**.
2. 구구몬은 **기술 1개로 시작**하고 **레벨이 오르면 기술을 배운다**(Lv **1·3·8·14·20**, 종마다 기술 5개, 장착 최대 3개).
3. 야생 구구몬을 **잡거나 쓰러뜨린 순간 2%** 로 그 구구몬의 **기술을 복사**. 장착이 3개로 가득 차 있으면 **하나를 지우고 장착하거나 포기**.
4. **캡슐 던지기·포획 과정 연출(원작 풍)과 효과음.**
5. 기술 추가 개발 **전부**: ① **기술 능력 차이**(위력 3단계 + 특수효과) ② **속성 상성**(단순) ③ **새 효과 그림** ④ **기술 사용 효과음** ⑤ **기술 관리 화면**.

진화 시스템은 나중에 넣는다(이번엔 건드리지 않음 — 기술은 종에 붙고 진화 단계와 무관).

## 1. 결정과 가정

| 항목 | 결정 | 출처 |
|---|---|---|
| 기술 고르기 | **문제를 풀기 전에 이번 차례 기술을 고른다.** 보기 버튼은 답 숫자만. 정답이면 고른 기술이 나감. 장착 기술이 **1개뿐이면 고르는 단계를 건너뛴다** | 사용자(추천 선택) |
| 기술 수·레벨 | 종마다 5개, Lv 1·3·8·14·20, 장착 최대 3개 | 사용자 |
| 능력 | 위력 3단계 + 특수효과 3가지(§2-6) | 사용자 |
| 상성 | 단순 상성: 강함 +1칸 / 약함 −1칸 (§2-7) | 사용자 |
| 복사 시점·확률 | 야생을 **잡았을 때**(`caught`)나 **퇴치했을 때**(`released`) **2%**, 도망은 제외 | 사용자 |
| 복사 대상 | 그 야생 구구몬이 자기 레벨에서 익힌 기술 중 무작위 1개(이미 아는 기술 제외, 후보 없으면 없음) | 가정 |
| 레벨로 배운 기술 | 레벨이 되면 **항상 "아는 기술"** 이 된다. 장착이 3개 미만이면 자동 장착, 가득이면 "바꿔 장착 / 장착 안 함(아는 채로 보관)". 보관한 기술은 관리 화면에서 언제든 장착 | 가정 |
| 복사한 기술 | 장착 3개 미만이면 자동 장착, 가득이면 "하나 잊고 장착 / 포기". **포기하면 복사 안 됨**. 복사하면 그 기술은 **아는 기술**이 되어 관리 화면에서 다시 장착할 수 있다 | 사용자+가정 |
| 포획 실패 | `retry`(다시 던지기) → **체력 일부 회복 후 재전투**. `escaped`·`angry` 그대로 | 가정 |
| 회복량 | 체력 최대 칸의 **절반(올림)** (`CAPTURE_FAIL_HEAL_RATIO = 0.5`) | 가정 |
| 적 공격 | 적 공격에는 **상성·위력을 적용하지 않는다**(지금 단계별 피해 그대로). 상성은 내가 때릴 때만 | 가정(어린이에게 불리한 규칙을 만들지 않음) |

## 2. 기술 시스템

### 2-1. 기술 표 (`src/domain/field/skills.ts`, 새 파일, 순수 로직)

- `SkillId` = 문자열 id(예: `cloud-1`…`cloud-5`, `legend-fluff-1`…). `SkillDef { id, species, slot(1~5), name, element, fx: FxName, power: 1|2|3, special?: 'heal'|'calm'|'clue', learnLevel }`.
- 종 11개(몬스터 8 + 황금 3) × 5개: **1~3번은 지금 이름 그대로**(`creatures.ts`의 `MOVES`·`LEGEND_MOVES`), **4·5번은 새 이름**(22개, 어린이가 읽기 쉬운 한국어, 종 분위기).
- 순수 함수: `learnedAt(species, level)`(그 레벨까지 익힌 목록), `newlyLearned(species, from, to)`, `knownSkills(entry)`(레벨로 익힌 것 + `copied`), `defaultSkills(species, level)`(익힌 것의 앞 3개), `skillDef(id)`, `rollCopy(rng, wildSpecies, wildLevel, known)`.
- 기술 이름·위력·효과를 바꿀 때는 이 파일 한 곳.

### 2-2. 저장 (`SpeciesEntry`)

- `skills: SkillId[]` — **장착한 기술**(1~3개). `copied: SkillId[]` — **복사로 얻은 기술**(장착 여부 무관). 레벨로 익힌 기술은 레벨에서 계산하므로 저장하지 않는다.
- 옛 저장: `mergeEntry`가 `skills`를 `defaultSkills(species, level)`로, `copied`를 `[]`로 채운다 → 레벨 8 이상이면 지금 기술 3개 그대로 장착(**옛 저장에서 기술이 줄어드는 일 없음**).
- 이상한 값(알 수 없는 id·다른 종의 레벨 기술 위조·중복·4개 이상·빈 목록)은 거르고, `skills`가 비면 `defaultSkills`로 채운다. `skills`는 **아는 기술**(레벨로 익힌 것 ∪ `copied`) 안에서만 허용. `copied`는 다른 종의 기술 id만 허용하고 중복을 거른다.
- `newSpeciesEntry(species, level, now)`: `defaultSkills`로 시작 기술을 정한다(새로 잡은 구구몬·스타터).
- CLAUDE.md 저장 네 곳: `createInitialSave`(필드 기본), `mergeSave`(`mergeField`/`mergeEntry` 깊게 채우기), `useGameStore.partialize`, `admin/DataSecurityPanels.tsx currentSave()`. 형식 추가라 키는 그대로.

### 2-3. 배우기 (레벨업)

- 레벨이 오르는 기존 정산 지점(`finishWildBattle`의 `addExp`)에서 `newlyLearned`를 구한다. 한 번에 여러 레벨이 올라도 레벨 순서로 처리.
- 장착이 3개 미만이면 **자동 장착** + 알림 "「새 기술」을 배웠어요!". 가득이면 선택창(§2-5): "이 기술과 바꿔서 장착" / "장착 안 함(배운 채로 둠)".

### 2-4. 복사 (2%)

- 전투 끝(`caught`·`released`) 정산에서 `rollCopy`: `COPY_CHANCE = 0.02`, 한 전투에 한 번. 당첨되면 후보 하나 선택.
- 장착 3개 미만이면 바로 복사·장착(알림 "○○에게서 「기술」을 따라 배웠어요!"). 가득이면 선택창: "하나 잊고 장착" / "포기".
- 복사한 기술은 원래 종의 **속성·효과·위력·특수효과를 그대로** 가져온다.
- E2E 스위치 `__GUGU_E2E_COPY__`(true면 복사 100%)를 `debugFlags.ts`에 더한다.

### 2-5. 선택창 (`SkillOfferDialog`, 새, 필드 화면)

- 새 기술 카드(이름·속성·위력 별·특수효과 글·출처) + 지금 장착 3개 버튼 + 포기/보관 버튼. 한 번에 하나씩, 큰 글자. 확정: `useGameStore.replaceSkill(species, removeId, addId)`.
- 제안은 세션 상태(`useSessionStore.skillOffers`, 저장 안 됨). 레벨로 배운 기술은 아는 기술로 남으므로 제안을 놓쳐도 관리 화면에서 장착할 수 있다. 복사 제안은 놓치면 사라진다.
- 떠 있는 동안 자동 새로고침을 막는다(`setUpdateBusy`).

### 2-6. 능력 (1번)

- **위력**은 야생 체력(칸)을 깎는 양이다. 체력 단위를 **칸**으로 바꾼다: 단계별 최대 체력 = `hitsToDizzy × CELLS_PER_HIT(2)` → 약함 10·보통 8·강함 6·강력 4. (정답 한 번 = 지금의 "한 번 깎임"은 위력 2칸 — 시작 기술이 위력 2라 **처음 전투 길이는 지금과 같다**.)
- 한 번에 깎는 칸 = `clamp(위력 + 상성, 1, 3)`(위력 1~3, 상성 ±1, 최대 3칸). 강력(4칸)도 최소 정답 2번은 필요(1번에 끝나지 않음). 칸 합이 최대 체력 이상이면 어지러움.
- **특수효과**(정답일 때만):
  - `heal`: **내 구구몬 체력 +1**(최대 체력 안에서, 상처는 그대로).
  - `calm`: **다음 문제 시간 +3초**(`CALM_BONUS_MS`).
  - `clue`: **다음 문제의 틀린 보기 하나를 미리 지운다**.
- **슬롯별 능력**(종 모두 같은 패턴 — 복사해도 그대로): 

  | 슬롯 | 레벨 | 위력 | 특수 |
  |---|---|---|---|
  | 1 | 1 | 2 | — |
  | 2 | 3 | 1 | heal |
  | 3 | 8 | 3 | — |
  | 4 | 14 | 2 | calm |
  | 5 | 20 | 2 | clue |

  (가정, 밸런스는 `skills.ts`에서 조정)
- 포획 실패 회복(§3)은 칸 단위: 현재 깎인 칸에서 `ceil(최대 칸 × 0.5)`만큼 되돌린다.
- 힌트·오답·시간 초과의 지금 규칙(다시 풀기, 적 공격 피해)은 그대로.

### 2-7. 속성 상성 (2번, `elements.ts`에 상성표)

속성: 풀·독·빛·물·번개·땅·불. **내 기술 속성(공격) → 야생 속성(방어)**.

| 공격 | 강함(+1칸) |
|---|---|
| 불 | 풀 · 독 |
| 물 | 불 · 땅 |
| 풀 | 물 · 땅 |
| 번개 | 물 · 독 |
| 땅 | 번개 · 불 |
| 독 | 풀 · 빛 |
| 빛 | 독 · 번개 |

- 판정 `matchup(공격, 방어)`: 방어가 공격의 강함 목록에 있으면 **강함**(+1), 방어의 강함 목록에 공격이 있으면 **약함**(−1), 둘 다거나 둘 다 아니면 보통(0). (독↔빛은 서로 강해 보통.)
- 기술 고르는 버튼 위에 **"효과가 커요!" / "별로예요"** 글자와 ▲▼ 표시(색에만 의존하지 않음). 정답으로 맞출 때 화면 글에도 한 줄.
- 황금 구구몬의 속성은 기반 종의 속성을 따른다.
- 이 표는 기술의 속성(복사한 기술은 원래 종 속성)에만 쓴다. 내 구구몬 본체 속성은 상성에 쓰지 않는다(기술이 곧 속성).

### 2-8. 기술 관리 화면 (5번)

- 위치: **도감 화면(`FieldDexScreen`)** 구구몬 상세에 "기술" 구역. 전투·상점 중에는 못 바꾼다(전투 화면에는 없음).
- 보이는 것: 장착 칸 3개 + 아는 기술 목록(레벨로 익힌 것 + 복사한 것, 아직 못 배운 레벨 기술은 "Lv 14에 배워요" 잠금 표시). 기술마다 이름·속성·위력 별·특수효과 글.
- 바꾸기: 아는 기술을 눌러 **장착**(빈 칸이면 바로, 3개 가득이면 바꿀 기술을 고름). 장착 해제는 1개를 남기는 한 가능(**최소 1개**). 저장은 `useGameStore.setSkills(species, ids)` 하나로(검증 후 한 번에 `set`).
- 쓰러진 구구몬도 기술은 바꿀 수 있다(체력과 무관).

## 3. 포획 실패 → 체력 회복 후 재전투

- `wildBattle.ts`의 `throwCapsule`: `retry` 결과를 **`healed`** 로 바꾼다. 어지러움이 풀려 `phase: 'question'`으로 돌아가고, 깎인 칸을 §2-6대로 되돌리고, 문제 시간을 새로 시작한다.
- 글: "앗! 캡슐에서 빠져나왔어요! 힘을 조금 되찾았어요!" (`battleText.ts`). 체력 막대가 늘어나는 것이 보이게(부드럽게 차오름 + 작은 반짝).
- 캡슐은 던질 때 소모(지금과 같음). 확률표(`throwOdds`)의 `retry` 칸 값은 유지하고 의미만 바뀐다(잡힐 확률·평균 캡슐 설계는 그대로).
- `escaped`·`angry`·캡슐 0개 퇴치는 그대로.
- 전투 흐름 변경이므로 구현·검토는 Opus.

## 4. 연출과 효과음

### 4-1. 캡슐 던지기 연출 (원작 풍)

던지기 버튼(`onCapsule`, 던지는 동안 입력 막음):

1. **던짐**: 내 쪽에서 야생 쪽으로 포물선, 공이 돈다 — 효과음 `throw`.
2. **빨려 들어감**: 닿으면 붉은 빛 번쩍과 함께 야생 구구몬이 공 안으로 줄어들며 들어간다(`wild__foe--capsule`) — `capsuleOpen`.
3. **떨어짐·튕김**: 땅에서 한 번 통통 — `capsuleBounce`.
4. **흔들림 3번**: 좌우로 3번(사이에 멈춤) — 흔들 때마다 `capsuleShake`.
5. **결과**: **잡힘** → 3번 다 흔든 뒤 `capsuleClick`(딸깍)과 별가루(`collect-burst`, 황금은 금빛) + `capture`. **실패**(회복·도망·화남) → 1~2번째 흔들림에서 공이 **열리며 튀어나옴**(`capsulePop`) 후 결과별 연출(회복은 §3). 결과는 난수 하나로 이미 정해진 것에 연출만 맞춘다.
- 길이 합쳐 약 3초 안. 동작 줄이기면 캔버스 효과는 빼고 흔들림만(기존 규칙). 새 효과가 필요하면 `effects.ts`에 한 줄씩.

### 4-2. 캡슐 효과음 (`src/audio/sfx.ts`, Web Audio 합성)

`throw`(휙) · `capsuleOpen`(슈웅) · `capsuleBounce`(통) · `capsuleShake`(딸깍) · `capsuleClick`(탁) · `capsulePop`(뾰옹). 기존 `capture`(잡았을 때) 재사용. 소리 끄기·첫 터치 뒤 재생 규칙 그대로.

### 4-3. 새 효과 그림 (3번)

- **속성마다 새 효과 2개**(14개)를 pixelfx 효과 목록에서 골라 `effects.ts`의 `EFFECTS`·`ELEMENT_FX`에 더한다 → 4번·5번 기술이 기존 3개와 다른 모양을 쓴다. 속성별 효과는 이제 5개(`ELEMENT_FX[속성]`이 5칸, 슬롯 번호 = 칸 번호).
- 새 14개도 기존과 같은 기준: **맞는 순간 효과 ≤0.6초**(`until÷speed`), 화소 무게중심을 재서 `center` 표에 적고 중심이 맞는 쪽 몬스터에 오도록(2차 후속 규칙), 황금 금색 팔레트, 뒤집기 지원. `tests/field/elements.test.ts`·`fxCenter.test.ts`가 21개→35개를 검사하도록 확장하고 `#/dev/field`에 버튼.
- 특수효과 표시용 작은 효과 1~3개(회복 반짝·시간 여유·힌트)도 같은 규칙(기존 효과 재활용 가능).

### 4-4. 기술 효과음 (4번)

- **속성별 효과음 7개**(풀·독·빛·물·번개·땅·불, 각 약 0.3초 이내 합성음)를 기술이 맞는 순간 틀고(내 공격·적 공격 모두 그 속성), 상성에 따라 **`superEffective`(강함)** / **`notVery`(약함)** 한 소리를 겹친다. 특수효과: `heal`(반짝 올라감)·`calm`(차분한 종)·`clue`(띵).
- 기술 **고르기 단계**의 탭음은 기존 `tap`. 소리 규칙은 4-2와 같다.

## 5. 전투 흐름 (고르기 단계 추가)

1. 문제가 나오기 전(새 문제마다): 장착 기술이 2개 이상이면 **기술 고르기 단계**(큰 버튼 최대 3개, 상성 글·위력 별·특수효과 표시). 하나뿐이면 자동 선택(건너뜀).
2. 고른 뒤 문제 시계가 시작(고르는 시간은 문제 시간에 안 셈, 고르기 단계는 `answerTimer`가 멈춘 채). 정답이면 고른 기술이 나가고 칸이 깎이고 특수효과 적용. 오답·시간 초과면 적이 공격하고(기존), 힌트 뒤 **같은 기술**로 같은 문제를 다시 푼다(다시 고르지 않음).
3. 적의 기술 이름·효과: 그 종이 그 레벨에서 익힌 기술 중 무작위(황금은 황금 기술).
4. `moveFx`는 `skillDef(id).fx`를 쓴다(속성·슬롯 → 효과).
5. E2E 스위치 `__GUGU_E2E_QUESTION__`·`NO_TIMER`는 고르기 단계와 함께 동작해야 한다(고르기를 건너뛰는 1기술 스타터가 기본이라 기존 E2E는 깨지지 않게).

## 7. 테스트 기준 (요지)

- 단위: 기술 표(55개, 레벨·위력·특수 패턴, 이름 중복 없음, 효과 id 존재), `defaultSkills`/`newlyLearned`/`knownSkills` 경계, `rollCopy`(0.02 경계·알고 있는 기술 제외·후보 없음), `matchup` 표 전수(49쌍, 독↔빛 보통), 칸 계산(위력×상성 clamp 1..3, 강력 한 번에 안 끝남), `healed` 회복 칸 4단계·황금, 특수효과 3종, `mergeEntry` 옛 저장·이상한 값·`copied` 검증, `partialize`/`currentSave`에 `skills`·`copied`, `replaceSkill`·`setSkills` 검증(최소 1·최대 3·모르는 기술 거부), 효과 ≤0.6초·무게중심 35개, 속성 효과음 이름.

- 시각: 375px에서 고르기 단계·선택창·관리 화면·던지기 연출·새 효과 35개 눈 확인.
