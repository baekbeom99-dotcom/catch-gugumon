# 별점수 오픈 · 주인공 색 꾸미기 · 시계 읽기 · 거꾸로 묻기 — 설계

## 왜
콘텐츠를 늘린다. 이미 만들어 둔 별점수를 켜서 "모으는 이유"를 만들고(주인공 꾸미기), 체육관에 시계 읽기를 더해 학습 범위를 넓히고, 마스터한 단은 거꾸로 묻기(나눗셈)로 다시 확인한다.

## 사용자가 정한 것
- **거꾸로 묻기**: 마스터한 단의 문제에만 섞는다. 화면은 **야생 전투 + 체육관 학습**. 마스터 도전(27초)은 지금처럼 정방향만.
- **별점수 오픈**: `STAR_POINTS_ENABLED = true`. 별점수·동상·계단 별 아이템이 살아난다.
- **주인공 꾸미기**: 이번엔 **색 바꾸기만**. 단위는 **세트 하나를 통째로**(머리색·윗옷·바지가 한 번에 바뀜). 구성은 ① 나라 국기 색 세트 ② 특정 캐릭터 느낌의 색 세트. **캐릭터 세트 이름은 상표를 쓰지 않는 중립 이름**(색만 따라 함). 국기 세트는 나라 이름 그대로.
- **악세서리**: 가능한지만 검토해서 적는다(아래 "악세서리 검토"). 이번에 만들지 않는다.
- **시계 읽기**: 체육관에 **트레이너 NPC 3명**(정각 / 5분 단위 / 1분 단위).

## 목표 / 비목표
- 목표: 위 기능 전부. 수치·표는 한 곳(`tuning.ts`·`costumes.ts`)에 둔다.
- 비목표: 악세서리 구현, 상점 꾸미기에서 색 자유 선택(팔레트), 상점 다른 탭 변경, 퀴즈 모험 변경, 마스터 도전 문제 모양 변경, 서버.
- 반(反)목표: 예전 저장이 깨지는 것, 별점수가 꺼져 있던 때의 기록(0)이 이상해지는 것, 야생 전투 흐름(타이머·단계 전환)이 달라지는 것.

## A. 거꾸로 묻기
- 모양: 같은 구구단 사실(a×b=P)을 나눗셈으로 묻는다. 두 가지: `P ÷ a = □`(답 b), `P ÷ b = □`(답 a). 0단·곱하는 수 0은 없음(필드 문제는 ×1~×9).
- **마스터한 단**(`training.mastered[dan]`)의 문제에만, 확률 `REVERSE_CHANCE`(tuning, 기본 0.25)로 바꿔 낸다. 마스터 안 한 단은 지금 그대로.
- 어디서: 야생 전투 문제(`planFieldQuestions`가 준 계획을 전투 문제 받는 곳에서 한 번 변환), 체육관 학습 모드(×1~×9 순서 중 일부를 같은 문제의 나눗셈 모양으로). 마스터 도전·상점 연습·계단·동상은 그대로.
- 기록: 맞고 틀린 것은 **원래 구구단 사실 id**로 기록한다(숙련도·틀린 문제 목록이 그대로 이어짐). 시간 규칙·보기 수(필드 3개, 학습 3개)는 그대로.
- 화면: `QuestionDisplay.equation`에 `op?: '×' | '÷'`를 더한다(없으면 ×). ÷일 때 `a = 나뉘는 수(P)`, `b = 나누는 수`, `result = 몫(빈칸이면 null)`. 문제 카드·읽어 주는 글(`spokenLabel`)·힌트 패널이 이 모양을 그릴 수 있어야 한다.
- 오답 보기: 정답 주변 값(±1, 같은 단의 이웃 몫) 중에서, 정답과 겹치지 않게.

## B. 별점수 오픈
- `featureFlags.ts`의 `STAR_POINTS_ENABLED`를 `true`로. 저장 칸(`field.starPoints`)은 이미 있다.
- 살아나는 것: 구구몬 발견·포획·훈련 보상 별(`STAR_*`), 레전드 보상 20, 동상(문제 7개, 별 5~15), 계단 위 별 아이템(황금·별 비율).
- **별점수 보기**: 필드 HUD(`FieldHud`)에 별 개수를 항상 보인다(이전엔 꺼져 있어 없었음). 별이 늘면 잠깐 +N 표시는 하지 않는다(YAGNI).
- E2E: 기본은 **꺼진 채로** 돌린다(`e2e/fixtures.ts`가 `__GUGU_E2E_STARS__ = false`), 별을 보는 스펙만 켠다. (앱 기본값이 true가 돼도 기존 E2E가 흔들리지 않게.)

## C. 주인공 색 꾸미기
### 데이터
- `src/domain/field/costumes.ts`(순수): `COSTUME_SETS` 표 — `{ id, name, group: 'flag' | 'concept', price, hair, shirt, pants }`. 기본 세트(`basic`, 지금 그림 그대로, 가격 0). `isOwned`, `canBuy`, `buy`, `equip` 순수 함수.
- 세트 구성(시작 목록, 나중에 표에 줄만 더하면 늘어남):
  - 국기(나라 이름 그대로): 한국·일본·미국·브라질·프랑스·이탈리아·독일·스페인 등 8~10개.
  - 캐릭터 느낌(중립 이름): 예) 노랑 번개 친구, 바다 노랑 네모, 빨강 모자 형제, 초록 닌자, 보라 마법사 등 6~8개. **실제 캐릭터·작품 이름은 코드·화면·문서 어디에도 쓰지 않는다.**
- 가격: 한 값(`COSTUME_PRICE`, 기본 50)에서 시작, 표에서 세트마다 다르게 바꿀 수 있다.
- 저장: `SaveData.field.costume: { owned: string[]; equipped: string }` (기본 `{ owned: ['basic'], equipped: 'basic' }`). **네 곳**(`createInitialSave`·`mergeSave` 깊게 채우기·`partialize`·`currentSave()`). 모르는 id는 병합 때 버리고 `basic`으로.
- 스토어 액션: `buyCostume(id)`(별 부족·이미 가짐·별점수 꺼짐이면 실패), `equipCostume(id)`(가진 것만). 별 차감은 한 곳에서.

### 그림 바꾸기
- 주인공 017 치비 시트(idle·walk·attack·front·back)에서 **머리(갈색)·윗옷(하늘색)·바지(파랑)** 화소를 색상 범위로 찾아 세트 색으로 바꾼다(`npcTint.ts`와 같은 방식: 채도·밝기는 원래 값을 따라가 결이 남는다). **피부·윤곽선·곡괭이·신발은 지킨다.** 곡괭이(청록)와 윗옷(하늘색)의 색상이 가까우니 구현자가 실제 화소를 보고 범위를 정하고 테스트로 고정한다.
- 순수 함수(캔버스 없음)와 굽기(캔버스, 캐시)를 나눈다. 굽기 결과는 세트별로 한 번만 만든다.
- 그림이 쓰이는 모든 곳에 같은 결과: 필드(`fieldRenderer`/`FieldScreen`), 무한의 계단(`StairsScreen` 앞모습), 상점 미리보기, `#/dev/field`. 그림 파일이 없으면 픽셀 주인공(`hero.ts`)이 나오며 그 경우 색 세트는 **적용하지 않아도 된다**(배포본에는 그림이 있음).
- 상점 미리보기는 서 있는 앞모습.

### 상점 「꾸미기」 탭
- 지금 `준비 중` 자리를 「꾸미기」로 바꾼다(`SHOP_TABS`). 위에 보유 별점수. 세트 카드(색 세 칸 + 이름 + 가격/「입기」/「입는 중」), 그룹(나라 / 캐릭터)으로 나눔.
- 사려면 별이 충분해야 하고, 이미 가진 세트는 공짜로 바꿔 입는다. 입으면 바로 필드 주인공에 반영.
- 문제 풀이 연습 없이 별로 산다(별은 이미 문제를 풀어 번 것).

## D. 악세서리 검토 (구현 안 함)
- **가능하다.** 주인공 시트는 4열×4행(방향 4 × 프레임 4)이고 머리가 프레임마다 위아래·기울기가 다르다. 모자류는 (시트 종류 × 방향 × 프레임)마다 "머리 꼭대기 앵커"가 필요하다. 앵커는 칸의 투명도에서 머리 꼭대기를 자동으로 재고, 어긋나는 칸만 표로 고치면 된다.
- 쉬운 것: 모자·머리띠·왕관(머리 위), 안경(앞모습만). 어려운 것: 망토(뒤·옆 방향마다 모양), 손에 드는 것(곡괭이와 겹침).
- 저장 쪽은 `field.costume`에 `accessory`를 나중에 더하면 되므로 지금 칸을 미리 만들지 않는다.
- 다음 단계(색 꾸미기 안정 뒤)에 모자 몇 개부터 시작하는 것을 권한다.

## E. 시계 읽기 (체육관 NPC 3명)
- NPC 셋: `clock-hour`(정각), `clock-five`(5분 단위), `clock-one`(1분 단위). `GYM_NPCS`에 `kind: 'clock'`, `level: 'hour' | 'five' | 'one'`. 자리는 구현자가 정하되 (a) 입구에서 걸어 닿을 것, (b) 기존 NPC·동상과 겹치지 않을 것, (c) 오른쪽 셈 트레이너 열 가까이 또는 빈 칸. `tests/field/gymMap.test.ts`가 지킨다.
- 도전만 있다(셈연습 트레이너와 같다): 9문제, 보기 3개, 하나도 안 틀리고 제한 시간 안에 끝내면 합격. 제한 시간 표 `CLOCK_TRAINER_MASTER_MS`(tuning; 시작값 정각 30초·5분 45초·1분 60초 — 제 판단, 한 곳).
- 문제: 아날로그 시계 그림 → "몇 시 몇 분?" 보기 3개(디지털 `3:30` 꼴 글).
  - 정각: 분 = 0, 1~12시. 5분: 분은 5의 배수. 1분: 분 0~59.
  - 오답 보기: 시침·분침을 바꿔 읽은 값, 시 ±1, 분 ±5(5분)/±1(1분). 서로 겹치지 않게.
- 열림: 정각은 항상, 5분은 정각 마스터 뒤, 1분은 5분 마스터 뒤(`isClockOpen`). 잠김 말풍선은 `gymTalk.ts`에.
- 보상: 도전 성공마다 무작위 필드 캡슐 `TRAINING_CAPSULES`(5), **해당 단계 첫 마스터**는 `TRAINING_FIRST_MASTER_CAPSULES`(20), **1분 첫 마스터는 레전드 구구몬 한 마리**(`legendGranted.clockOne`, 별 보상 `STAR_LEGEND_REWARD`는 기존 규칙대로). 별점수: 훈련 성공 보상 `STAR_TRAINING`.
- 저장: `training.clock: Partial<Record<ClockLevel, {bestMs, at}>>`, `training.legendGranted`에 `clockOne` 추가. 네 곳 + `mergeTraining` 깊게 채우기. 기록 화면(`FieldRecordsScreen`)에 시계 줄 추가.
- 화면: `#/field/training/clock/:level`. 문제 틀은 기존 `QuizBoard`·`ArithTrainerScreen`을 일반화해 쓴다. `BoardQuestion`에 `clock?: { h: number; m: number }`와 보기 글 만드는 법(`choiceText?`)을 더하고, 문제 카드가 `clock`이 있으면 시계 SVG(숫자 판·시침·분침)를 그린다. 보기 값은 `h*60+m`(숫자)로 두어 기존 판정을 그대로 쓴다.
- 저학년 모드: 영향 없음(시계는 두 모드 모두 같음).

## 저장 데이터 정리
- 새 칸 두 곳: `field.costume`, `training.clock`(+`legendGranted.clockOne`). `SCHEMA_VERSION` 그대로(빈 값 채우기). 별점수 칸은 이미 있다.
- 모델 분배(CLAUDE.md): 저장 데이터를 건드리는 구현(costume·clock 저장, `mergeField`)은 `opus-expert`, 끝나면 `opus-reviewer`로 브랜치 전체 검토. 순수 규칙·화면은 일반 에이전트(Sonnet).

## 확인
- 단위: 거꾸로 묻기 변환(마스터한 단만·확률 0/1·기록 id), 나눗셈 오답 보기, `COSTUME_SETS` 표 고정(id 중복 없음·색 범위·이름에 금지어 없음), `buyCostume`·`equipCostume`(별 부족·중복·꺼짐), `mergeField`(예전 저장 + 옛 값 버리기), 시계 문제(정각 분 0·5분 배수·보기 겹침 없음·오답에 정답 없음), `isClockOpen`, 합격 판정, `gymMap`(NPC 자리·도달), 색 바꾸기 순수 함수(머리·옷·바지만 바뀜, 피부·윤곽선 그대로).
- E2E: 별이 켜진 채 상점 꾸미기 산 뒤 입기, 시계 정각 도전 합격→다음 단계 열림, 마스터한 단의 거꾸로 묻기 문제가 전투에 나옴(스위치로 고정).
- 화면: 375px에서 꾸미기 탭·시계 문제 화면·체육관 배치·HUD 별 표시를 직접 확인.

## 제 판단 목록 (바꿀 수 있음)
- 거꾸로 묻기 확률 0.25, 꾸미기 가격 50, 시계 제한 시간(30·45·60초), 시계 단계 순서 열림, 1분 첫 마스터 레전드 지급, 세트 개수·이름.
- 별을 HUD 항상 표시(+N 알림 없음).
- 픽셀 주인공(그림 없음)에는 색 세트 미적용.
